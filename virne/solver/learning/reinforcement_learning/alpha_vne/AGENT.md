# AlphaZero SFC Solver (`alpha_vne`)

This directory contains a sophisticated solver for the Service Function Chain (SFC) / Virtual Network Embedding (VNE) problem. The implementation is heavily inspired by DeepMind's AlphaZero algorithm, which masterfully combines deep reinforcement learning with Monte Carlo Tree Search (MCTS) to achieve superhuman performance in complex strategy games.

## Overview

The goal of this solver is to learn a robust policy for embedding SFC requests onto a physical network, maximizing the acceptance rate and the revenue-to-cost ratio. It treats the sequential placement of virtual nodes as a game. For each virtual node, the solver must decide which physical node to place it on. The MCTS algorithm serves as a powerful, lookahead "planning" module to explore the vast search space of possible placements, while a neural network provides the "intuition" to guide the search effectively.

## Core Architecture

The system is built on a decoupled **Actor-Learner** model, which allows for simultaneous data generation and model training.

- **The Actor** "plays the game." Its role is to make decisions and solve incoming SFC requests. In doing so, it generates high-quality data about which sequences of moves lead to successful embeddings.
- **The Learner** runs in the background. It continuously ingests the data generated by the Actor and uses it to train and improve the central neural network.
- **The Replay Buffer** is the communication channel between them. The Actor writes trajectories (sequences of states, actions, and final outcomes) to the buffer, and the Learner samples from it.

This creates a virtuous cycle: a smarter network leads to better decisions, which generates higher-quality data, which in turn makes the network even smarter.

## Key Components

#### 1. The Orchestrator (`alpha_zero_sfc_solver.py`)

This is the high-level manager. The `AlphaZeroSFCSolver` class is responsible for:
- Initializing the Actor and launching the Learner in a separate process.
- Interfacing with the main simulation environment, receiving SFC requests.
- Delegating the solving process to the Actor.
- Managing the overall training loop (epochs, distributed workers, etc.).

#### 2. The Decision-Making Actor (`actor_optimized.py`)

The Actor's job is to handle a single SFC request. It does this by sequentially placing each virtual node. For each placement decision, it invokes the MCTS engine to determine the best move.

#### 3. The MCTS Engine (`node.py` and `cpp_core/`)

This is the "thinking" part of the solver. For each decision, it builds a search tree to find the best action. The process involves four steps, repeated many times (the `computation_budget`):

1.  **Selection:** Traverse the existing tree by choosing the most promising nodes, guided by a formula (PUCT) that balances known performance and the neural network's policy.
2.  **Expansion:** When an unexplored "leaf" node is reached, expand it by creating new child nodes representing all possible next moves.
3.  **Evaluation:** At a new leaf, the neural network's **value head** is called to estimate the quality of the position. This is used instead of a slow, random simulation (rollout).
4.  **Backup:** The value obtained from the evaluation is propagated back up the tree, updating the statistics of all nodes along the path.

After the search is complete, the Actor chooses the move that was explored most often.

#### 4. The Neural Network "Brain" (`net.py`)

This `ActorCritic` network provides the intuition that makes the search intelligent. It has two heads:
- **Policy Head (the "Actor"):** Predicts which moves are most promising from a given state. This guides the MCTS to focus its search on good areas of the search space.
- **Value Head (the "Critic"):** Predicts the expected final outcome (e.g., success or failure) from a given state. This provides a high-quality evaluation at the leaves of the search tree.

#### 5. The Learner (`learner.py`)

The `AlphaZeroLearner` runs in the background. It continuously:
1.  Samples batches of completed "games" (trajectories) from the replay buffer.
2.  Trains the `ActorCritic` network by minimizing a loss function that teaches the policy head to predict the MCTS search results and the value head to predict the game's final outcome.
3.  Saves the updated network weights, which the Actor will then load to improve its future decisions.

## C++ Acceleration

Python is excellent for high-level logic, but its interpreted nature makes it slow for the millions of simple, repetitive calculations inside the MCTS search loop. To achieve high performance, the most computationally intensive components have been ported to C++.

- **What was moved to C++?** The entire "hot loop" of the solver now runs in compiled, native code:
    1.  The MCTS search algorithm itself.
    2.  The tree and state data structures.
    3.  Crucially, the **graph pathfinding algorithms** (e.g., k-shortest-paths) used for link-mapping feasibility checks.

- **How does it work?** The `cpp_adapter.py` acts as a bridge. The Python Actor prepares the initial problem and hands it over to the C++ `MCTSEngine`. The C++ engine performs the entire search, including all state transitions and constraint checks, at native speed. The only time it calls back to Python is to get evaluations from the PyTorch neural network, which is itself a highly optimized C++/CUDA library.

This design provides the best of both worlds: the flexibility and ease of use of Python for the overall framework, and the raw performance of C++ for the computational core.

## How to Build and Run

### 1. Standard Training Run

1.  **Prerequisites:** Ensure your `conda` environment (`virne`) has the required dependencies installed: `pytorch`, `cmake`, `pybind11`, and the `cuda-toolkit` if using a GPU.

2.  **Build the C++ Extension:** A helper script automates the entire build process. From the project root, run:

    ```bash
    ./virne/solver/learning/reinforcement_learning/alpha_vne/cpp_core/build.sh
    ```

    This script compiles the C++ code and automatically creates a symbolic link so that Python can import the module without any `PYTHONPATH` modifications.

3.  **Run the Solver:** To run a training session using this solver, execute the main `virne` application and specify the solver name in the configuration.

    ```bash
    python main.py solver.solver_name=alpha_zero_sfc [other_configs...]
    ```

### 2. Ablation Study: K-Values Sweep

To evaluate the impact of the `k_shortest` parameter, you can use the provided sweep script. This tool automates the process of running multiple training sessions, each with a different value for `k`.

**Example Command:**

```bash
python tools/train_alpha_zero_k_sweep.py \
  --dataset-dir dataset/training \
  --k-values 1-15 \
  --max-workers 2 \
  --num-epochs 1 \
  --steps-per-epoch 64 \
  --max-training-steps 64 \
  --export-dir results/alpha_zero_sfc/exported_models \
  --extra-overrides \
  training.use_cpp_mcts=true \
  training.use_neural_network=true \
  training.use_nn_policy=true \
  training.use_nn_value=true \
  training.computation_budget=64 \
  training.c_puct=1.4 \
  training.num_workers=1 \
  training.min_buffer_size=32 \
  training.max_empty_batches=1800 \
  training.save_interval=64 \
  training.save_checkpoint_history=true \
  training.disable_trajectory_writing=false \
  training.gpu_batch_size=16 \
  training.gpu_timeout_ms=5 \
  training.use_batched_gpu=true \
  training.if_use_random_training_seed=false \
  training.seed=0 \
  experiment.seed=0 \
  use_fixed_dataset=true
```

**Key Arguments:**

- `--k-values 1-15`: Defines the range of `k` to test. The script will launch a separate run for k=1, k=2, ..., k=15.
- `--max-workers 2`: Runs up to 2 of the `k-value` experiments in parallel.
- `--dataset-dir`: The directory containing the training dataset(s) to be used for each run.
- `--export-dir`: The base directory where the trained models from each run will be saved.
- `--extra-overrides`: A powerful feature to pass Hydra configuration settings to each training job. This is used here to precisely control the MCTS engine, C++ backend, and training parameters for every run in the sweep.
